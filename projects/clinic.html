The problem.

Booking an appointment involves patients, doctor availability and staff oversight. The project models those roles and connects each appointment to its own chat thread.

Inside the project.

  • Patient, doctor and admin roles with different pages and permissions.
  • Available-slot generation from doctor schedules and booking-conflict checks.
  • Appointment-linked chat over STOMP / WebSocket with a REST fallback.
  • Spring Security with JWT, Swagger documentation and service test files.

How it fits together.

01Patient / doctor UI
02JWT + REST
03Booking service
04Database + chat

The project explores role boundaries, schedule data and realtime communication while keeping booking rules on the backend.

Current state.

Public source application with an H2 default database and PostgreSQL-ready configuration. It is presented as a software project, not a deployed clinical service.
