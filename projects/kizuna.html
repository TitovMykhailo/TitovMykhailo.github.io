An adaptive mesh-routing protocol for unstable autonomous devices: neighbor discovery, link evaluation, gradual neighbor admission, primary and backup paths, and resilience modes — with a Docker lab and a web simulator to make it visible.

The problem

When links are unstable and nodes disappear, a static route stops working. KIZUNA explores how autonomous devices can discover each other, decide which links to trust, share topology and keep traffic moving as conditions degrade.

What I built

  • A binary packet envelope (magic “KIZU”) and six core messages: HELLO, LSA, DATA, SOS, LAYER and PREDICT, sent over UDP/IPv6 multicast.
  • Gradual neighbor admission with repeated proof of identity, so the mesh doesn’t instantly trust every device it hears.
  • A link-state database and routing engine that keep a primary and a backup path, plus a relay advisor that prefers capable, under-used nodes.
  • Four resilience layers (normal, degraded, emergency, survival) and four traffic classes, so control and SOS traffic survive while bulk traffic is shed first.
  • A 12-container Docker lab with reproducible fault injection (tc netem, container stop/start), gateway failover, and a web dashboard of nodes, links and paths.

How it works

  1. 1Discover neighbors
  2. 2Evaluate and admit links
  3. 3Flood topology (LSA)
  4. 4Compute primary + backup paths
  5. 5Adapt forwarding by layer

Results

Public repository with the protocol core, a reproducible 12-node lab and a dashboard. The test suite (167 tests) passes on a clean checkout. The roadmap now turns the lab protocol into a real Linux overlay with a kiz0 TUN interface.

What I learned

Separating the protocol core from the simulator, collector and dashboard made each layer testable on its own — and made it possible to boot the daemon on a real node without the simulator.
